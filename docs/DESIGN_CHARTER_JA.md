# PANORAMA typeGPT — 設計憲章 / Universal Sound Synthesis Environment

2026-10-27 / Prototype 0.4.2 時点の方針。これは最終仕様ではなく、原点となった思想を保全するための上位指針。

## 中核命題

> 「すべてのシンセを一つにまとめたシンセ」ではなく、「音を生成する仕組み自体を創造できるシンセ」。

PANORAMAは、既存の音源方式を選択する製品ではなく、生成原理を分解し、相互に励振・共鳴・変調・変換・再構成できる設計環境を目指す。機能数が多いだけでは最高傑作とは呼ばない。

## 三大理念

1. **生成可能性 (Generativity)** — 現実に存在する楽器を模倣するだけでなく、未経験の音響構造を組み立てられる。
2. **解析可能性 (Analyzability)** — 音を周波数・位相・包絡・過渡・ノイズ・共鳴の観点で観察し、逆合成で編集可能な構造を探索する。
3. **操作可能性 (Controllability)** — 初心者は直感的に、専門家は数理的に、音の変化と生成過程を扱える。

## 音響アーキテクチャの方向性

- 音源と処理器を、固定された方式名だけではなく「励振」「発振」「振動・共鳴」「変換」「変調」「制御」「イベント」「空間伝播」という異なる役割へ分解する。
- VA / FM / PM / 位相変形 / Additive / Spectral / Granular / Physical Modeling / Procedural・Chaosを段階的に実装する。
- 各音源方式の**相互作用**を中心にする。たとえば物理共鳴体の出力でFMを変調し、加算合成の部分音を別のモデルへ励振として供給する。
- ルーティングは音声・制御・イベントの型、チャンネル、単位、処理順、帯域、レイテンシーを管理する。フィードバックは遅延や安定性の証明を要求する。
- 物理モデリングは楽器名ではなく物質・形状・励振から設計する。現実にない物性も安全に扱う。
- 声門・声道・フォルマントを独立した音響コンポーネントとして取り込み、歌声専用エンジンに限定しない。
- 長期目標：Inverse Synthesis、Sound Space、構造モーフィング、新DSPモジュール追加環境。

## 音質について

複雑さそれ自体は美しさを保証しない。原音の倍音構造、時間変化、非線形処理、帯域制限、包絡の滑らかさ、ステレオ／モノラル再生、演奏表現、CPU負荷を同じ設計問題として扱う。客観的な音響測定と人間の聴感評価を混同しない。

## 過去の判断の継承

- 0.3の「Midnight Geometry」は接続構造が評価された一方、VA Oscillatorの原音は好みに合わないとのフィードバックがあった。このため0.4ではHarmonic Additive / Phase Warpに踏み込み、Midnight Geometry Reforgedを設けた。
- ユーザーの音色嗜好（Sylenth1、Plasmonic、Absynth 6のアルゴリズム合成）は参考情報。ただし**PANORAMA typeGPTではGPT側の音響設計思想を優先**し、好みに合わせることを必須としない。特化型Sylenth2はユーザーの音色理想を主軸にする。
- 0.1 / 0.2音色のビット完全保存を開発の絶対条件としない。比較用の旧ソース／WAVは残し、品質向上のための変更を許容する。
- typeGPTとtypeCodexは**別系統の独立開発**。相互のソース、WAV、プリセットの流用はしない。

## 現在の実装と未到達事項（0.4.2）

- 実装済：C++ DSP、32プリセット、固定9ノードの音声グラフ、2レーンのMod Matrix、Harmonic Additive / Phase Warp、簡易Modal Resonator、JUCE用GUIとVST3ソース。

- **未検証：Windows VST3コンパイル、pluginval strictness 5、Studio One実機、JUCE GUI統合実行、すべての高域条件でのエイリアシング特性**。
